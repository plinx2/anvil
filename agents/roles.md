# ロール

対話ロールの構成は確定。**状態に属する 9 ロールと、起票の 1 ロールで、計 10 ロール**。それとは別に、**バックグラウンドロール**がある(下記。今は PR 作成担当)。各ロールの詳細は [roles/](roles/) に書いている。

| 状態 | ロール | 主な仕事 |
|---|---|---|
| (起票。TODO の前) | PBI 起票担当 | 簡単なやりたいことから、タイトル・ペイン・ゲイン・AC を起票する。分割の依頼も受けて起票する。形はプロジェクトコンテキストに従う |
| リファイン | AC 担当 | AC の明確化、価値と AC のずれの確認、AC の提案。HOW に寄らない。分割の判断と依頼 |
| DEV リファイン | 実装方針担当 | 実装方針の提示。SP は人間が決める。デザインの要否も決める。分割の判断と依頼 |
| デザイン設計 | デザイン設計担当 | 画面の見た目と振る舞いの設計。デザインが必要なチケットだけ |
| 機能設計 | 機能設計担当 | 機能の設計。プロジェクトの採用ツールに従う |
| テスト設計 | QA/QE | 設計と AC を受けてテスト設計 |
| 実装 | コーダー | 方針に沿って、レビューしやすく実装 |
| 機能動作確認 | 機能動作確認担当 | 実際に動かして、機能を確認 |
| デザイン確認 | デザイン確認担当 | デザイン設計と実際の画面を見比べる。デザインが必要なチケットだけ |
| レビュー | レビュワー | 規約適合、1 年後に読めるか、開放閉鎖の原則 |

状態は、5 つのカテゴリ(着手前 / リファイン / 設計 / 実装 / 完了)のどれかに属し、**1 つの状態に 1 つのロール**がいる。カテゴリを超えるところに**ゲート**(設計前、実装前、完了前)がある。

## ルール(確定)

- **機能とデザインの分割**: 設計と動作確認で、状態も分ける(デザイン設計 / 機能設計、機能動作確認 / デザイン確認)。1 つの状態に 1 つのロール。
- **「デザインの要否」は DEV リファイン時に決める**。チケットが持つ。不要なら、anvil が「デザイン設計」と「デザイン確認」の状態をスキップする。
- **順序**: 設計は**デザイン設計 → 機能設計**(デザイン設計が機能設計の前提)。動作確認は**機能動作確認 → デザイン確認**。
- **外したロール**: 指揮者、教育者。
- **PO 役の AI**: 標準では置かない。後から置ける余白を持つ。
- **オーナーの関与は、ゲートでの確認で足りる**(確定)。「実装方針とレビューには、できる限り入る」という方針は、取り下げた。
- **ロール別のコンテキスト**は、プロジェクトごとに与える(プロジェクトコンテキストの `roles/<ロール>.md`)。
- **プロジェクト固有の読み込みの指示は、ロールの定義に書かず、ロールコンテキストで与える**(例:「プロジェクトのテスト方針を読む」)。ロールの定義は、プロジェクトに依存しない形に保つ。
- ロールの指示の改修は、振り返りの提案を経て、オーナーが採否を判断する。
- **全ての対話ロールは、作業の完了時に振り返りを保存する**。各ロールの文書には個別に書かない。

## モデルと、AI エージェントの種類(確定。オーナーの指示)

- **モデルは、基本は Sonnet 5.5**(`claude-sonnet-5-5`)。**ものによって Haiku 5.5**(`claude-haiku-5-5`)を使う。
- **AI エージェントの種類は、Claude Code に限らない**。将来、Copilot、Codex など、さまざまなエージェントを扱えるようにする。anvil の内側(ports)は、特定のエージェントの概念を前提にせず、エージェントの種類ごとの実装を、並べて足せる形にする。
- **Haiku 5.5 を使うのは、軽い仕事だけ**(確定): 決まった入力から決まった出力を作る、**バックグラウンドロール**(今は [PR 作成担当](roles/pr-writer.md))。対話ロールは、まず Sonnet 5.5 のまま。振り返りを見て、足りるところから Haiku に下ろす。
- **モデルの指定の場所**(確定): anvil の**ロールごとの設定**。プロジェクトごとに上書きできる。
- **エージェントの種類は、anvil の起動時に選ぶだけ**(確定)。チケット、ロール、プロジェクトの単位では選ばない(anvil 全体で 1 つ)。

## ロールの種類(確定)

- **対話ロール**: herdr のペインでエージェントが動き、人間が会話できる。状態に紐づくロール(AC 担当、実装方針担当など)と、PBI 起票担当。
- **バックグラウンドロール**: herdr のペインを使わず、anvil が内部で `claude` を実行して動く。人間との会話は無い。決まった入力から決まった出力を作る。例: [PR 作成担当](roles/pr-writer.md)。
- **バックグラウンドロールは、こまごま用意する可能性がある**(オーナーの見立て)。
